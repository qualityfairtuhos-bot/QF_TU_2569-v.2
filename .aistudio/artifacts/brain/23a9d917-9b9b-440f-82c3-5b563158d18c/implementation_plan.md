# สรุปผลการปรับปรุงระบบและการดำเนินการ

## 1. ข้อความแจ้งผลการประเมินในอีเมลแบ่งตามผลการประเมินของแต่ละผลงาน
- ได้ทำการอัปเดตระบบส่งอีเมลแจ้งผลการประเมิน (`promptWorkStatusNotificationEmail`) ในหน้าผู้ดูแลระบบ (Admin) ให้มีเทมเพลตมาตรฐานตรงตามเอกสารประกาศผลทางการ 3 รูปแบบ:
  1. **สถานะผ่าน – Oral Presentation**
     - หัวข้อ: `แจ้งผลการคัดเลือกผลงานวิชาการ ประเภท Oral Presentation – งานมหกรรมคุณภาพโรงพยาบาลฯ ครั้งที่ 19 ประจำปี 2569`
     - กำหนดเวลานำเสนอผลงานละ 12 นาที (นำเสนอ 10 นาที, ถาม-ตอบ 2 นาที)
  2. **สถานะผ่าน – Poster Presentation (e-Poster)**
     - หัวข้อ: `แจ้งผลการคัดเลือกผลงานวิชาการ ประเภท Poster Presentation – งานมหกรรมคุณภาพโรงพยาบาลฯ ครั้งที่ 19 ประจำปี 2569`
     - รายละเอียด e-Poster กำหนดเวลานำเสนอผลงานละ 5 นาที (พร้อมแจ้งทีมงานยกป้ายเตือน)
  3. **สถานะไม่ผ่าน – ไม่ได้รับการคัดเลือก**
     - หัวข้อ: `แจ้งผลการพิจารณาผลงานวิชาการ – งานมหกรรมคุณภาพโรงพยาบาลฯ ครั้งที่ 19 ประจำปี 2569`
     - ข้อความขอบพระคุณและให้กำลังใจในการส่งผลงานในโอกาสต่อไป
- **ระบบเลือกเทมเพลตให้อัตโนมัติ**:
  - เมื่อผู้ดูแลระบบปรับสถานะผลงาน ระบบจะตรวจจับสถานะ (`ACCEPTED_ORAL`, `ACCEPTED_POSTER`, `REJECTED`, ฯลฯ) และเลือกเทมเพลตที่ตรงกับผลงานให้อัตโนมัติทันที
  - มี Dropdown ให้ Admin สามารถสลับเปลี่ยนรูปแบบข้อความ (Oral / Poster / ไม่ผ่าน) ได้ทันทีในหน้าต่างเดียวกัน
  - กล่องข้อความและหัวข้อยังคงสามารถพิมพ์แก้ไขหรือเพิ่มเติมรายละเอียดได้อิสระก่อนกดส่ง หรือเลือกไม่ส่งอีเมลได้

## 2. เพิ่มเมนูสำหรับตรวจสอบผลการประเมิน (ลิงก์ภายนอก)
- **เมนูด้านบน (Top Navigation Bar)**:
  - เพิ่มเมนู **"ผลการประเมิน" (Results)** แทรกระหว่างเมนู *"สถานะผลงาน"* และ *"กำหนดการ"* ตามตำแหน่งที่ท่านระบุ
  - เมื่อคลิกจะเปิดไปยังหน้า `https://hospital.tu.ac.th/qualityfair/th/results` ในแท็บใหม่ทันที
- **ปุ่มในส่วน "ระบบบริการผู้เข้าร่วมงาน" (Participant Services)**:
  - ปรับเลย์เอาต์การ์ดเป็น 4 ปุ่ม โดยเพิ่มปุ่มสีฟ้าสดใส **"ตรวจสอบผลการประเมิน (Evaluation results)"** ข้างปุ่มส่งผลงาน
  - เมื่อคลิกจะพาไปยังลิงก์ `https://hospital.tu.ac.th/qualityfair/th/results` โดยตรงเช่นกัน

## 4. แก้ไขปัญหาแนบไฟล์นำเสนอผลงานไม่ผ่าน (ขนาดไฟล์ 12 MB)
1. **สาเหตุ**:
   - การส่งไฟล์ขนาด 12 MB ผ่านการเข้ารหัส Base64 จะมีขนาดข้อมูลเพิ่มขึ้นเป็น ~16.8 MB ซึ่งเกินขีดจำกัดขนาด Payload ของ Serverless Function / Cloud Gateway บนโฮสติ้ง (เช่น ขีดจำกัด 4.5 MB ของ Vercel) ส่งผลให้การเชื่อมต่อไปยัง Backend ถูกตัดขาด (413 Request Entity Too Large)
2. **การแก้ไข**:
   - **ระบบ Chunked Upload**: เพิ่มระบบแบ่งท่อนไฟล์ขนาดใหญ่ (`uploadFileInChunks` และ action `uploadFileChunk`) ซึ่งจะตัดแบ่งข้อมูล Base64 เป็นชิ้นเล็กๆ ขนาด ~1.5 MB ต่อคำขอ ทำให้ไม่ติดขีดจำกัด 4.5 MB ของ Vercel
   - **แถบแสดงความคืบหน้า (Progress Bar)**: แสดง % ความคืบหน้าแบบ Real-time ระหว่างกำลังอัปโหลด (เช่น `กำลังอัปโหลดไฟล์นำเสนอ... 25% (ชิ้นที่ 3/11)`) ทั้งในหน้าติดตามผลงานของผู้ส่งผลงาน (`index.html`) และหน้าจัดการของ Admin (`admin.html`)
   - **ทางเลือกแนบลิงก์ Google Drive**: เพิ่มช่องสำหรับระบุลิงก์ Google Drive ของไฟล์นำเสนอฉบับจริงในหน้าต่างอัปโหลด เพื่ออำนวยความสะดวกสำหรับไฟล์ขนาดใหญ่มาก หรือกรณีที่ผู้ส่งผลงานแชร์ไฟล์ไว้บน Google Drive แล้ว
   - **ปรับปรุง Backend & Apps Script**: ฝั่งเซิร์ฟเวอร์ (`/api/gas`) รองรับการรวมชิ้นส่วนไฟล์ก่อนส่งต่อไปยัง Google Drive พร้อมเพิ่ม `maxDuration = 120` วินาที และขยายสถานะที่อนุญาตให้อัปโหลดไฟล์นำเสนอใน Google Apps Script ให้ครอบคลุมทุกสถานะที่ผ่านการคัดเลือก

## 5. แก้ไขรูปแบบวันที่ปิดรับไฟล์นำเสนอผลงานในการตั้งค่าระบบ
1. **สาเหตุ**:
   - ช่องกรอก *"ปิดส่งไฟล์นำเสนอภายในวันที่ ...... เวลาคือ 23.59 น."* ด้านล่าง ดึงข้อมูลดิบในรูปแบบ ISO String เช่น `2569-11-10T16:59:00.000Z` มาแสดงโดยไม่ได้แปลงเป็นรูปแบบ พ.ศ. ทำให้แตกต่างจากช่องด้านบนที่เป็น `10/11/2569 23:59`
   - เมื่อกดบันทึกการตั้งค่า ฟังก์ชันตรวจสอบวันที่ไม่รองรับสตริงที่มี Milliseconds/Timezone ส่งผลให้ระบบแจ้งเตือนข้อผิดพลาด: `PresentationUploadCloseAt: กรุณากรอกเป็น dd/mm/พ.ศ. HH:mm` และไม่สามารถบันทึกการตั้งค่าได้
2. **การแก้ไข**:
   - **จัดรูปแบบให้อัตโนมัติ**: เมื่อโหลดหน้าตั้งค่าระบบ (`loadSettings`) ข้อมูลวันปิดส่งไฟล์นำเสนอทั้งสองจุด (ด้านบนและด้านล่าง) จะถูกแปลงเป็นรูปแบบมาตรฐานไทย `10/11/2569 23:59` เสมอ
   - **เชื่อมโยงข้อมูลสองจุดอัตโนมัติ (Sync)**: เมื่อผู้ดูแลระบบแก้ไขวันที่หรือเวลาในช่องใดช่องหนึ่ง อีกช่องจะอัปเดตตามแบบ Real-time ทันที
   - **ระบบแปลงและตรวจสอบที่ยืดหยุ่น**: ปรับปรุงฟังก์ชัน `parseBeDateTime`, `formatBeDateTime` และฝั่ง Backend ให้รองรับทั้งรูปแบบ วัน/เดือน/พ.ศ. HH:mm และ ISO String โดยแปลงเป็นปี พ.ศ. และเวลาที่ถูกต้องได้อย่างแม่นยำ ไม่เกิดข้อผิดพลาดในการบันทึกอีกต่อไป
